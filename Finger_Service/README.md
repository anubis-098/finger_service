# CJ Finger Service — มาโครดึงสแกนนิ้ว

รุ่น **1.2.0** รองรับอัปเดตจาก GitHub `anubis-098/finger_service` โดยตรวจเมื่อเปิดและทุก 12 ชั่วโมง เมนู System tray → **Check updates** ใช้ดาวน์โหลด/ยืนยันติดตั้ง โปรแกรมตรวจ SHA-256 ก่อนติดตั้ง สำรองไฟล์เดิม และเก็บค่าตั้งค่า/คิว TXT ไว้ ต้องติดตั้ง ZIP รุ่นที่มี updater นี้ด้วยตนเองครั้งแรกก่อน รายละเอียดสำหรับผู้พัฒนาอยู่ใน `UPDATES.md` ของ source code

รุ่นแก้ Login Session: กรอก Username/Password ด้วยคีย์บอร์ดเพื่อให้หน้าล็อกอินได้รับ input events ตรวจโฟกัสก่อนพิมพ์และระหว่างพิมพ์ ไม่อ่านค่ารหัสผ่านกลับมา และรอข้อความล็อกอินสำเร็จก่อนดำเนินการต่อ หากหลุดโฟกัสจะหยุดเพื่อไม่พิมพ์ลงหน้าต่างอื่น แพ็กเกจแก้ไขอยู่ใน `publish-login-fix` / `CJFingerService-LoginFix.zip` และยังรองรับการส่งไฟล์เข้า Server

โปรแกรม Windows System tray สำหรับ WEB8 NEXT Data Export ตามภาพใน `examples/FingerService`
รุ่นนี้ทำ **มาโคร เก็บ TXT ในเครื่อง และส่งเข้าเว็บ Server** โดยเปิดการส่งใน Settings ใส่ Server URL และ Service token ก่อนใช้งาน หากปิดการส่งจะเก็บไฟล์ในเครื่องเหมือนเดิม

## เชื่อม Client → Server

1. บน Server ใช้เว็บรุ่นที่มี API `/api/fingerprint-service/` (อัปเดตด้วย `docker compose up -d --build`) ไม่ต้องรีเซ็ตฐานข้อมูล ตารางรับข้อมูล Service สร้างอัตโนมัติเมื่อใช้งานครั้งแรก
2. Super Admin เปิด **Fingerprint logs → ตั้งค่า Client / สร้าง Service token** ตั้งชื่อเครื่อง แล้วสร้าง Token คัดลอกเก็บไว้ เพราะจะแสดงเพียงครั้งเดียว
3. คัดลอกทั้งโฟลเดอร์ `publish-client` ไปเครื่อง Client และ Exit Finger Service รุ่นเก่าก่อนเปิด `CJFingerService.exe`
4. ใส่ **Server URL** เช่น `https://attendance.company.com` หรือ `http://192.168.1.20:3000` ไม่ต้องเติม API path ใช้ IP/hostname ของ Server ที่เครื่อง Client เข้าถึงได้ ไม่ใช้ localhost หากอยู่คนละเครื่อง
5. ใส่ **Service token** แล้วกด **Test connection** เพื่อทดสอบ URL/Token โดยไม่ส่งสแกน หากใช้ HTTP ใน LAN ให้ติ๊กอนุญาต HTTP (ข้อมูลและ Token ไม่เข้ารหัสระหว่างส่ง) แนะนำ HTTPS สำหรับใช้งานจริง
6. ติ๊ก **ส่ง TXT ไปยัง Server** กำหนดโปรแกรม WEB8/โฟลเดอร์/บัญชีของจริง กด Save แล้ว **Run now** เพื่อทดลอง กด Start สำหรับรอบอัตโนมัติทุก 30 นาที
7. ดูจำนวนเพิ่มใหม่และรายการซ้ำในเว็บ Fingerprint logs พร้อมเวลารับไฟล์และชื่อ Client สถานะเขียวหมายถึงติดต่อภายใน 40 นาทีล่าสุด ไม่ใช่การตรวจออนไลน์ตลอดเวลา

ส่งครั้งละไม่เกิน 10 ไฟล์ในคิวต่อรอบ ไฟล์ที่ส่งสำเร็จจะมี `uploaded.json` เป็นใบตอบรับและไม่ส่งซ้ำ ไฟล์เดิมยังอยู่ทั้งหมด ถ้าส่งไม่สำเร็จจะค้างใน `pending` และลองส่งเมื่อรอบ Export ถัดไปสำเร็จ หรือกด **Retry uploads** เพื่อส่งคิวโดยไม่เปิด WEB8 คิวเก่าจะถูกส่งด้วยเมื่อเปิดใช้การส่ง จึงควรใช้โฟลเดอร์ข้อมูลทดสอบแยกเมื่อทดลอง Dummy ห้ามนำไฟล์ Dummy เข้า Server จริง

URL/Token ไม่ถูกส่งต่อเมื่อ Server ตอบ redirect ให้ใส่ URL ปลายทางที่ถูกต้อง ใบตอบรับบันทึก Server ที่รับไฟล์ไว้ การเปลี่ยน URL ไม่ส่งไฟล์ที่มีใบตอบรับแล้วซ้ำไป Server ใหม่

## เปิดใช้งาน

1. เปิด `publish-client/CJFingerService.exe` (Windows x64) แนะนำใช้เครื่องหรือ VM สำหรับงานนี้โดยเฉพาะ
2. ที่หน้าตั้งค่า เลือกไฟล์ `.exe` ของ WEB8 NEXT และโฟลเดอร์ Export TXT ที่มีอยู่จริง
3. Username ค่าเริ่มต้นคือ `getdata` กรอกรหัสผ่านที่ให้ไว้ รหัสผ่านจะเข้ารหัสด้วย Windows DPAPI ผูกกับบัญชี Windows นี้ ไม่เก็บใน log หรือ source code
4. ช่วงวันที่ตั้งต้น **ย้อนหลัง 3 วันถึงวันนี้** อิงเวลาไทย เช่น วันที่ 29 ก.ย. ดึง 26–29 ก.ย. รอบทำงานคงที่ **30 นาที**
5. กด **บันทึก** แล้วคลิกขวาที่ไอคอนถาดระบบ เลือก **ดึงข้อมูลตอนนี้** เพื่อทดลองรอบแรก
6. เมื่อรอบแรกทำงานถูกต้อง เลือก **เริ่มรอบอัตโนมัติ** เปิดตัวเลือกเริ่มพร้อม Windows ได้ใน Settings (เฉพาะบัญชีผู้ใช้ปัจจุบัน)

ถ้ายังไม่รู้ไฟล์โปรแกรมหรือ URL สามารถบันทึกค่าที่ยังไม่ครบได้โดยไม่เปิดรอบอัตโนมัติ ไม่ต้องใส่ URL เพื่อใช้มาโคร

## ลำดับงาน

เปิด/ค้นหาโปรแกรมจาก executable ที่ตั้งค่า → ปุ่ม `1. ล็อกอินเข้าระบบ` → กรอก Username/Password → `Log in` → ตรวจข้อความล็อกอินสำเร็จ → `ใช้ Session นี้` → ตั้งวันเริ่มและวันสิ้นสุด → `2. ดึงข้อมูล` → รอรอบใหม่มี `status: ready` → `3. บันทึกไฟล์ txt` → รอไฟล์ใหม่เขียนเสร็จ → ตรวจสามคอลัมน์ → คัดลอกเข้าคิวเก็บไว้

- ใช้ Windows UI Automation ค้นหาชื่อปุ่ม/ช่องกรอกเป็นหลัก ไม่ผูกพิกัดหน้าจอ
- ช่องวันที่กรอกแยกวัน/เดือน/ปีตามรูปแบบ `dd/MM/yyyy` ในภาพอ้างอิง แล้วอ่านค่ากลับมายืนยันก่อนดึงข้อมูล
- ใช้ OCR เป็นทางสำรองสำหรับปุ่มที่ไม่มี UI Automation โดยยอมคลิกเฉพาะข้อความปุ่มที่ตรงและพบตำแหน่งเดียว ต้องมี OCR ภาษาที่กำหนดติดตั้งใน Windows
- ตรวจ process และหน้าต่างปลายทางก่อนคลิก หากหลุดโฟกัส/ล็อกจอ/หาปุ่มไม่ได้ จะหยุดรอบนั้นและแจ้งเตือน
- ถ้าไม่เห็นสถานะใหม่ของการดึงข้อมูล จะ timeout เพื่อหลีกเลี่ยงนำข้อมูลเก่ามาอ้างว่าดึงสำเร็จ กรณีโปรแกรมจริงไม่แสดง loading/ไม่เปลี่ยนสถานะ ต้องปรับตัวตรวจจับจากการทดสอบเครื่องจริง
- ไม่มีรอบซ้อนกัน แต่ละรอบมี worker แยกและจำกัดเวลารัน ไม่ปิด/kill โปรแกรม WEB8 เมื่อ worker หมดเวลา
- ไม่ลบ TXT ต้นทางและไม่ลบไฟล์คิวเก่า

## ไฟล์และการตั้งค่า

ค่าเริ่มต้นอยู่ใน `%LOCALAPPDATA%\CJFingerService`

| รายการ | ที่เก็บ |
|---|---|
| ค่าตั้งค่าและรหัสผ่านเข้ารหัส | `settings.json` |
| TXT ที่ดึงได้ | `pending/<run-id>/<filename>.txt` |
| ข้อมูลรอบ/ที่มา/checksum และรหัสส่งซ้ำ | `pending/<run-id>/manifest.json` |
| ใบตอบรับ Server | `pending/<run-id>/uploaded.json` |
| ตำแหน่งโค้ดเมื่อ worker ล้มเหลว ไม่รวมรหัสผ่าน | `worker-error.log` |
| Log ไม่รวมรหัสผ่าน/เนื้อหาไฟล์ | `service.log` |

ไฟล์ใน `pending` เก็บข้อมูลส่วนบุคคลของพนักงาน ควรใช้บัญชี Windows สำหรับงานนี้และจำกัดสิทธิ์เข้าถึงโฟลเดอร์ การย้ายรหัสผ่านที่เข้ารหัสไปอีกเครื่อง/อีกบัญชีจะใช้ไม่ได้ ให้กรอกใหม่ใน Settings

ตั้ง environment `CJ_FINGER_SERVICE_DATA` ได้หากต้องการย้ายโฟลเดอร์ข้อมูล เช่น สำหรับการทดสอบที่ไม่ใช้ค่าจริง

## ข้อจำกัดก่อนทดสอบจริง

- ต้องมี interactive Windows session ที่ไม่ล็อกหน้าจอ การออกจากระบบ Windows จะหยุดโปรแกรม ไม่ใช่ Windows Service ใน Session 0
- โปรแกรมอาจดึงหน้าต่างขึ้นมาและใช้เมาส์ หลีกเลี่ยงใช้งานเมาส์ระหว่างรัน ใช้สิทธิ์ระดับเดียวกับ WEB8
- ยังไม่ทราบ executable และยังไม่ได้ทดสอบกับโปรแกรมจริง จึงอาจต้องปรับชื่อคอนโทรล/สถานะตามเวอร์ชันที่ติดตั้ง โดยเฉพาะ WebView Login
- OCR ภาษาไทยไม่พร้อมในเครื่องพัฒนาที่ตรวจสอบ ถ้า UI Automation ใช้ไม่ได้ ต้องเตรียม OCR ที่เครื่องปลายทางก่อนใช้งานสำรอง
- โปรแกรมยังไม่ได้เซ็น digital signature องค์กรสามารถเซ็นไฟล์ก่อนกระจายใช้งานได้
- Token ถูกเข้ารหัสด้วย DPAPI ฝั่ง Client และเก็บเฉพาะ hash ฝั่ง Server เพิกถอนได้จาก Super Admin โดยไม่ลบประวัติหรือสแกน

## Build และทดสอบ

ใช้ .NET 10 SDK บน Windows:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Finger_Service\build.ps1
```

ผลลัพธ์ `publish/CJFingerService.exe` รวม .NET runtime สำหรับ Windows x64 และ `ocr.ps1` ให้นำทั้งโฟลเดอร์ publish ไปใช้งาน

`--self-test` ทดสอบ parser/DPAPI ส่วน `--automation-test` เปิดหน้าต่าง **TEST FIXTURE** จำลองและทดสอบ login/session/date/ready/export โดยไม่ติดต่อระบบสแกนนิ้วจริง ควรตั้ง `CJ_FINGER_SERVICE_DATA` เป็นโฟลเดอร์ทดสอบก่อนรัน

ผลตรวจเวอร์ชันนี้: Build ผ่าน, parser/DPAPI ผ่าน และทดสอบครบลำดับกับ TEST FIXTURE ผ่าน รวมการตรวจวันเริ่ม/วันสิ้นสุดในไฟล์ TXT ที่ Export จริง ทั้งนี้ยังไม่ใช่ผลทดสอบกับ WEB8 ที่เครื่องต้นทาง

อ้างอิง: [Microsoft UI Automation InvokePattern](https://learn.microsoft.com/en-us/dotnet/api/system.windows.automation.invokepattern.pattern?view=windowsdesktop-10.0), [Microsoft OCR sample](https://github.com/microsoft/Windows-universal-samples/blob/main/Samples/OCR/cs/OcrFileImage.xaml.cs)
# ปุ่ม Start และเวลาเริ่มอัตโนมัติ

เปิด Settings จาก System tray แล้วเลือกวัน–เวลาในช่องเวลาเริ่ม จากนั้นกด **Start** เพื่อบันทึกและเริ่มรอตามเวลา Windows ของเครื่อง หากไม่ติ๊กเวลาเริ่ม หรือเวลาที่เลือกผ่านแล้ว จะเริ่มทันที หลังจากนั้นทำซ้ำทุก 30 นาที ไม่ใช่กำหนดเวลาเริ่มใหม่ทุกวัน

ปุ่ม **Save** บันทึกตามสถานะช่องเริ่มรอบอัตโนมัติ ส่วน **Pause schedule** ใน System tray หยุดรอบถัดไป โดยไม่ยกเลิกรอบที่กำลังทำงานอยู่ **Run now** ใช้ดึงทันทีและนับรอบถัดไปอีก 30 นาที โปรแกรมจะไม่ทำงานซ้อนกัน หากรอบหนึ่งนานเกิน 30 นาที จะพักอีก 30 นาทีหลังจบ

หน้าต่างตั้งค่าลดขนาดเหลือประมาณ 620 × 565 และเลื่อนได้ ตัวตั้งเวลาไม่ตรวจทุกวินาที เมื่อ Pause จะหยุด Timer และเมื่อรอจะตั้ง Timer ถึงเวลารอบถัดไปโดยตรง ต้องเปิดโปรแกรมและ Windows session ไว้เพื่อทำงาน
